# データソースの走査

**取得できるのに取っていない指標を洗い出し、Issue にするまで。**

これまで 7 回以上やっている (#188〜#200 FRED / #202 #204 統計ダッシュボード / #222 財務省 /
#224 Finnhub / #226 e-Stat / #228 日銀 / 日本の中古住宅)。**手順を飛ばした結果の失敗が 5 件**
記録されているので、順に踏む。

## 手順

### 1. 提供元の全系列を列挙する

**キーワード検索を信じない。** 統計ダッシュボードの検索は**完全一致しか効かず**、
「住宅」でも 0 件を返す (#228 の調査で判明)。部分語で 0 件だったときは、
**引数なしで全一覧を取って手元で絞る**。

```
統計ダッシュボード: getIndicatorInfo (引数なし) → 全 5,822 指標 / 4.0 MB
e-Stat 統計 API:    getStatsList?searchWord=... (appId 必須)
FRED:               系列ページ / カテゴリを辿る
日銀:               getMetadata?db=<DB名> → 系列コードと日本語名の対応表
財務省 Fiscal Data: エンドポイントごとに fields と meta.total-count
```

**系列名が取れる経路を選ぶ。** 日銀の一括ダウンロード `co.zip` はコードと値だけで
**名前が無く** (54,831 行)、どれが業況判断 DI かを推測することになる。
`getMetadata` なら名前で特定できる。**名前で特定できない経路は使わない。**

### 2. 取得済みと突き合わせる

`data/indicators.json` の `source` を出所ごとに数え、未取得を出す。

```bash
python3 -c "
import json, collections
d = json.load(open('data/indicators.json')); d = d.get('indicators', d)
print(collections.Counter(v['source']['adapter'] for v in d.values()))
"
```

### 3. 現行か停止かを実データの最終期で確認する

**行数や存在だけで判定しない。** `HOUSTJP` は 546 行返るが中身はエラーページの HTML だった (#129)。

停止していた実例:

| 系列 | 停止 |
| --- | --- |
| 景気動向指数 2015年基準 | 2023-04 |
| 法人企業景気予測調査 `0003200132` | 2019Q1 (現行は `0003326000`) |
| `ADPWNUSNERSA` | 2026-06 DISCONTINUED |
| `JPNPERMITMISMEI` | 2008 |

**検索で最初に返る表が現行とは限らない** (#154 #226)。必ず最終期を見る。

### 4. 一次情報で単位と桁を確認する

**`note` を信じない。指標マスタの `note` が誤っていて、それを写して 2 回間違えた。**

| Issue | 指標 | 書いた単位 | 実際 |
| --- | --- | --- | --- |
| #198 | 商工業貸出 | 百万ドル | **十億ドル** |
| #212 | 自発的離職・採用 | 人 | **千人** (実データも 3,232) |

FRED は系列ページの `series-meta-value-units`、e-Stat は `@unit`、日銀は `UNIT_J`。
確認したら `sourceUnits` に**原文のまま**記録する (#212)。

**実データの桁も見る。** 最新値が想定の桁に収まるかを機械で照合できる。

### 5. 1 レスポンスに複数系列が混ざらないか確認する

**これが最頻の罠。同じ型を 4 回踏んでいる。**

| Issue | 何が混ざったか |
| --- | --- |
| #96 | 10年債入札に TIPS。`original_security_term` と `inflation_index_security` の両方で絞る |
| #129 | 月次/四半期/年度 と 原数値/季調値。`cycle` と `isSeasonal` の両方が要る |
| #222 | 平均利率に 16 系列。`security_type_desc` と `security_desc` の両方 |
| #226 | BSI に軸が 5 つ。`cat05` はメタ情報の一覧で見落とし、データを取って気付いた |

**軸を列挙する設計にしない。** 受信側で「**応答に出てきた軸をすべて見て 1 種類に絞れているか**」
を検査する (`parseStatsData` がこの形)。知らない軸が増えても黙って別物を掴まない。

**点数も見る。** 値だけ比べると、絞り込みが外れて同じ月に複数値が入る事故を見逃す。

### 6. 既存指標と重複しないか

同じものを別経路で取らない。日本の失業率は FRED (`LRHUTTTTJPM156S`) でも取れるが、
値が一致するので統計ダッシュボードに揃えた (#180)。**データソースは増やさない。**

**恒等関係にあるものは表示しない。** `dfii10` は `DGS10 − T10YIE` と恒等的に一致するため
検算にだけ使う (#115)。平均消費性向は米国では `100 − 貯蓄率` とほぼ同じなので入れない (#178)。

### 7. Issue に落とす

**実装せず Issue へ** (開発フロー 1〜3)。Issue に書くこと:

- 取れるものと**実測した直近値**
- **履歴の範囲**（何年から取れるか）
- 既存指標と重複しない理由
- 手順 3〜5 で見つかった罠（停止した旧表・軸・単位）
- 新しいデータソースなら **ADR が要る**ことと、代替案との比較観点

## 取れなかったときに書くこと

**「取れない」は調べ尽くした結論としてしか書かない** (#170 の教訓)。
#156 で「家計調査の月次消費支出は使えない」と書いたが**誤り**で、停止していたのは
`家計消費指数` の方だった。#135 でも「ゴールドは過去に遡って取り直せない」と書いたが、
履歴ページが直近 50 営業日を返していた。

書くときは**どの経路を当たって何件だったか**を数字で残す。

```
統計ダッシュボード: 全 5,822 指標の一覧を取得 →「中古」「既存」で 0 指標
e-Stat 統計 API:   「不動産価格指数」「既存住宅販売量指数」で 0 件
```

## 秘密情報の扱い

- **ローカルの `.env` を読み込む**: `set -a; . ./.env; set +a`
  (`NODE_OPTIONS="--env-file=..."` は使えない)
- `.env` が無い / 鍵が CI にしか無いときは、使い捨てのワークフローを
  `on: push` でブランチに置いて 1 回だけ回す。**終わったら必ず消す**
- **鍵を出力に出さない。** URL を例外やログに載せるとクエリ文字列の appId がそのまま残る。
  `safeQueryLabel` の形にする
