# autopilot — 確認をまとめてから止まる

**判断が要るたびに止まらない。決められるものは進め、判断が要るものを積み、しきい値で一度に聞く。**

引数でしきい値を渡せる (`/autopilot 5`)。**既定は 3。**

## 進め方

1. 作業を進める
2. 判断が要ることが出たら、下の分類に従って**即座に聞く / キューに積んで進む**のどちらかを選ぶ
3. キューがしきい値に達したら止まり、**全部まとめて**出す
4. 回答を受けたら再開する

## 分類 — これが要点

### A. 即座に聞く (キューに積まない)

しきい値を待たずに止める。**溜めても意味がない、または溜めては危ないもの。**

- **取り返しがつかない / 外に出る操作** — force push、ブランチやデータの削除、
  公開物の変更、外部サービスへの送信。**しきい値と無関係に必ず事前に確認する**
- **残りの作業が全部その回答に依存する** — 積んでも次に進めないので待つだけ損
- **どちらの仮定で進めても、外れたら丸ごと手戻り** — 実装の方向が変わる分岐

### B. キューに積んで進む

**仮定を置いて進められるもの。** 進めた上で、後でまとめて出す。

- 表示の細部（色・並び順・見出しの文言）
- 複数案があるが、どれでも後から変えられるもの
- 「ついでに直すか」レベルの発見（Goal 外の問題は Issue 起票のみで進む）
- しきい値・許容差の具体値（**実測してから決める**。決めた根拠を添えて出す）

積むときは**仮定を置いて進めた事実と、その仮定**を必ず記録する。後で覆せるようにするため。

### C. 聞かない

**自分で決めて進む。** キューにも積まない。

- 既に CLAUDE.md やこれまでの判断で答えが出ているもの
- 一次情報を見れば確定するもの（**推測で決めず、調べる**）
- 慣習的な既定があるもの

## 止まるタイミング

次のどれかで止まる。

- キューが**しきい値に達した**
- 分類 A が出た
- **残りの作業が全部ブロックされた**（キューがしきい値未満でも止まる）
- 依頼された範囲を**やり切った**

## 止まったときの出し方

**まとめて、決められる形で出す。**

- 各項目に**推奨案を添える**。「A / B / C どれ？」より「A を推す。理由は…」の方が即答できる
- 選択肢が 3 つ以上なら**番号を振る**（「どちらも」と言われて解釈がぶれた実例がある）
- **置いた仮定を一覧で出す**。覆したいものがあればそこで言ってもらう
- 選択肢が 2〜4 個に収まり互いに排他なら `AskUserQuestion` を使う。
  そうでなければ本文に番号付きで書く

## 進めている間のルール

**開発フローは省略しない。** autopilot は「着手指示を待つ」ステップを代替するだけで、
それ以外は通常どおり。

- 課題を見つけたら**実装せず Issue へ**。Issue 無しで着手しない
- 1 Issue = 1 PR、`closes #N`、main 直 push はしない
- typecheck / test / build / `pnpm verify` を通してから PR
- **マージ後は CI を確認する**。失敗を報告しないまま次に進まない
- 定期バッチを変えたら `workflow_dispatch` で手動実行して成否を確認する

**進捗は黙って進めない。** 1 つの Issue を片付けるごとに、何をしたかは短く残す。
止まるときにまとめて報告する。

## 報告に含めるもの

- 完了したもの（Issue 番号と、**実測値で示した結果**）
- **置いた仮定**と、覆せる範囲
- 積んだ確認事項（推奨つき、番号付き）
- **確認手順**（URL / 操作 / 期待挙動。UI 変更が無いなら不要と判断した理由）
- 損失が出ていれば「今回の損失」（自分のミスも同じ形式で書く）

## しきい値の目安

| 値 | 向くとき |
| --- | --- |
| 1〜2 | 方向性が固まっていない、初めて触る領域 |
| **3** | **既定。** 手順が確立していて、判断が独立している |
| 5 以上 | 定型作業の連続。長時間まとめて任せたいとき |

**しきい値を上げるほど、外れたときの手戻りが大きくなる。** 分類 A を厳しく見積もること。
