# ADR-0010: シラーPER (CAPE) は Robert Shiller 本人の公開データから取る

- 状態: 採用
- 日付: 2026-08-24
- 関連: #291 / #271 (PER の過去分布) / #109 (定義の異なる指標を同じ軸に混ぜない原則)

## 背景

ユーザーから「シラーPER (CAPE、景気循環調整後 PER) を表示していないか」との確認があり、
追加の依頼を受けた。既存の Forward/実績 PER (単年の利益で計算) とは別に、過去10年の
インフレ調整後平均利益で割ったシラーPERを新規に追加する。

FRED にはシラーPERが無い (ISM 新規受注指数などと同じく、著作権のある独自データセット)。

## 候補

| 案 | 一次情報か | 無料枠・登録 | 形式 | 更新頻度 | 不適合点 |
| --- | --- | --- | --- | --- | --- |
| **A. shillerdata.com (`ie_data.xls`)** | ○ (Shiller 本人が公開) | 無料、登録不要 | Excel (.xls、旧バイナリ形式) | 月次 (公式) | 明確な利用許諾の記載が無い (免責事項のみ)。Excel パースの新規依存が要る |
| B. multpl.com (HTML scrape) | × (二次ミラー、「courtesy of Robert Shiller」表記) | 無料、登録不要 | HTML table | 実測で最新の取引日付まで出ており、公式の月次更新より高頻度 (毎日、指数値を当てはめて再計算している可能性) | 一次情報ではなく、更新頻度の違いから値が公式とズレる可能性がある (未検証)。HTML 構造変化に弱い |

## 判断

**候補 A (shillerdata.com) を採用**。

- 一次情報を優先する原則 (#65: 代替指標は同等でないと明記する、と同じ判断軸)
- 実データで到達性を確認済み: `https://img1.wsimg.com/blobby/go/e5e77e0b-59d1-44d9-ab25-4763ac982e53/downloads/e27e58c1-8ae0-488c-a976-a298708c7175/ie_data.xls` が 200 を返す (1.67MB)
- 候補 B は一次情報ではなく、実測で最新日付が公式の月次更新より先行しているため
  (multpl.com 実測: 2026-08-21 時点のデータあり。Shiller 本人のファイルは 2026-08 分が
  最新で日次の粒度を持たない)、**定義が公式と食い違うリスクがある**

## 実データで確認した形式

`ie_data.xls` (Composite Document File V2 = 旧バイナリ Excel 形式、`.xlsx` ではない)。

- シート: `Disclaimer` (免責事項のみ) と `Data` (本体)
- `Data` シートは 0〜7 行目がタイトル・複数行ヘッダー、**8 行目 (0-indexed) からデータ**
- 列 0 = `Date` (後述の独自形式)、列 12 = `CAPE` (P/E10)
- CAPE は **1881-01 から**開始 (P・D・E は 1871-01 からあるが、CAPE は過去10年平均利益を
  要るため10年遅れて始まる)
- 末尾に近い行は脚注 (`"Oct '25/July/Aug CPI estimated"` 等) が数値列に紛れることがある。
  数値として解釈できない行は欠測として飛ばす
- 実測時点 (2026-08-24) で最新値は 2026-08、CAPE = 41.177621。**直近 1〜2 か月分は
  CPI が推計値の場合がある**ため、確定値ではない可能性がある (#100 の GDPPOT と同種の注意)

### 日付形式の罠

**月が 1 桁の場合、小数点以下がそのまま省略される** (例: 10月 → `2025.1`、1月 → `2025.01`)。
`2025.1` を文字列としてそのまま `.` で分割すると月を取り違える。**必ず `toFixed(2)` で
2桁に揃えてから分割する** (`2025.1.toFixed(2)` → `"2025.10"`)。これをテストで固定する。

## 実装方針

- 新規アダプタ `src/lib/adapters/shiller.ts` を追加し、**10個目のデータソース**にする
- Excel (旧バイナリ形式含む) のパースに `xlsx` (SheetJS Community Edition、Apache-2.0)
  を新規依存として追加する。`exceljs` は旧バイナリ `.xls` を読めないため候補から外した
- 財務省 (ADR-0006) と同じく**全期間を毎回取り直す** (1,748 件程度で差分取得の複雑さに
  見合わない)
- 表示は既存の Forward/実績 PER とは**重ねずに別チャート**にする (#109、#116〜#118 で
  適用済みの原則)。定義 (単年利益 vs 過去10年平均利益) が違うものを同じ軸に混ぜると
  「PERが上がった」のか「定義の違い」なのか判別できなくなる
- 過去分布のパーセンタイル表示 (#271 の `HistoricalDistribution`/`buildDistribution`) を
  シラーPERにも適用する。窓は既存と同じ5年に揃え、新しい閾値は追加しない

## 不適合点

- Excel パースライブラリの新規依存が増える (`xlsx`)。npm 本体は 2023年頃から更新が
  止まっているが、Apache-2.0 で実績があり、旧バイナリ形式の読み取りに対応する数少ない
  選択肢のため許容する
- 明確な利用許諾の記載が無い (免責事項のみ)。既存の FactSet PDF・S&P/Dow Jones (FRED経由)
  と同じく `copyright: "restricted"` として扱う
- xls の列位置・シート名がバージョンで変わるリスクがある。列位置ではなくヘッダー行の
  ラベル文字列 (`CAPE`) を探して列を特定する実装にし、構造変更で気付けるようにする
