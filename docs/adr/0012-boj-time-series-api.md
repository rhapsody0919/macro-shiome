# ADR-0012: 日銀時系列統計データ検索サイトの API を 8 つ目のデータソースにする

- ステータス: 採用
- 日付: 2026-08-30
- 関連: #228 (短観 業況判断DI)、#338 (企業向けサービス価格指数)、#226 (BSI、日銀短観の代替として先に採用)

## 背景

#226 で「日銀短観は e-Stat に無い」ことを確認し、法人企業景気予測調査の BSI を代替として
採用した。その後、日銀短観そのものに**登録不要の JSON/CSV API があること**が判明した (#228)。

別途、泉さんの記事の調査 (#337 と同じ調査) で、企業向けサービス価格指数 (SPPI) が
日銀の利上げ判断に連動する指標として追跡されていることが分かったが、統計ダッシュボード・
e-Stat のどちらにも SPPI は無い (#338)。日銀の統計は政府統計ではないため、e-Stat 系の
データソースにそもそも載らない構造は #228 (短観) と同じ。

**どちらも同じ「日本銀行時系列統計データ検索サイト」の API で取得できることを実機で確認した**
ため、1 つの ADR で両方の採否を判断する。

## 一次情報で確認したこと

### API の構成 (登録不要)

エンドポイント: `https://www.stat-search.boj.or.jp/api/v1/<API名>`

| API | 用途 |
| --- | --- |
| `getMetadata` | 系列コードと系列名 (日本語・英語) の対応表を `db` 単位で返す |
| `getDataCode` | 系列コードを指定して時系列を取る。カンマ区切りで複数系列を 1 リクエストで取れることを確認済み |

パラメータ: `db=<データベースコード>`、`code=<系列コード>` (getDataCode)、`format=json`、`lang=jp`。

**`db` が必須。** 省略すると `400 DBが指定されていません` を返す。短観は `db=CO`、
企業向けサービス価格指数は `db=PR02` (物価指数系は `PR01`〜`PR04` に分かれ、`PR02` が
「企業向けサービス価格指数」であることをトップページの一覧で確認済み)。

**存在しない系列コードを渡すと明示的にエラーになる** (`400 指定した系列コードは
存在しません：1番目のコード`)。系列が改廃されればここで検知できるため、#66 のような
「別物を掴む」失敗を防げる。`getMetadata` の日本語名との突き合わせも合わせて行う。

### 短観 業況判断DI (#228 で確認済みの値を再確認)

```
TK99F1000601GCQ01000  D.I./業況/大企業/製造業/実績    最新 2026Q2 = 22
TK99F2000601GCQ01000  D.I./業況/大企業/非製造業/実績  最新 2026Q2 = 37
```

履歴は製造業が 1974Q2〜、非製造業が 1983Q2〜。BSI (2004Q2〜) より 20〜30 年以上長い。
単位は `%ポイント`、頻度は `QUARTERLY`。

### 企業向けサービス価格指数 (SPPI、#338)

```
PRCS20_5200000000%  [基本分類指数] 総平均（前年比）  最新 2026-07 = 3.6%
```

**Issue に書いた市場予想との比較用の実測値 (前年比+3.6%) と一致した。** 公表の前年比を
そのまま使う (#162 の教訓、指数は 2020年=100 の水準しか出ないため自前で前年同月比を
導出すると桁数の関係でずれる可能性があるが、日銀は前年比を系列として公表しているので
導出は不要)。頻度は `MONTHLY`、1986-01〜現在まで欠測なし。

### 日付形式が両者で違う

| DB | 日付形式 | 例 |
| --- | --- | --- |
| `CO` (短観) | `YYYYQ` (5 桁、末尾 1 桁が四半期番号 1〜4) | `202602` = 2026年第2四半期 |
| `PR02` (SPPI) | `YYYYMM` (6 桁) | `202607` = 2026年7月 |

統計ダッシュボード (`YYYYMM00`)・e-Stat 統計 API (`YYYY00MMMM`) とも異なる**3 つ目の日付形式**。
既存の `toMonthlyDate`/`toQuarterlyDate` (estat-dashboard.ts) や `parseEstatDate` (estat-api.ts)
を流用せず、`boj.ts` に専用の変換関数を作り、他形式を渡すと `null` を返すことをテストで固定する
(#160 の教訓と同型)。

### 利用規約・レート制限 (`api_notice.pdf`)

- **登録・API キー不要**
- **クレジット表示が必須**: 「このサービスは、日本銀行時系列統計データ検索サイトの API 機能を
  使用しています。サービスの内容は日本銀行によって保証されたものではありません。」を
  `/terms` に掲載する
- 明示的な req/min の上限は無いが、「短時間における高頻度のアクセス」を禁止事項として明記。
  他ソースと同様に 1 秒間隔のレート制御を入れる (FRED と同じ方針)
- 予告なく機能停止・仕様変更・アクセス制限があり得る (SLA無し、免責事項あり)。ただし
  これは e-Stat ダッシュボードや財務省 Fiscal Data も同様の性質で、本プロジェクトの
  無料スタックが元々受け入れている制約の範囲内

## 候補の比較

| 案 | 無料 | 登録 | 系列名の照合 | 運用負荷 | 不適合点 |
| --- | --- | --- | --- | --- | --- |
| **日銀時系列統計 API (`getDataCode`/`getMetadata`)** | ○ | **不要** | ○ (`getMetadata`で名前つき) | 低 | クレジット表示の追加対応が要る |
| 一括ダウンロード (`co.zip`) | ○ | 不要 | **×** | 中 | Shift-JIS・系列コードのみで名前が無い (54,831行)。コード表PDFもコードを載せていない。#66 と同型の「推測で選ぶ」リスクを負う |
| 追加しない (現状維持) | - | - | - | - | 短観 (#228) は BSI より 20年以上長い実績データを取りこぼす。SPPI (#338) は日銀の利上げ判断に連動する指標として代替が無い |

## 決定

**日銀時系列統計データ検索サイトの API を 8 つ目のデータソースとして採用する。**
`getDataCode`/`getMetadata` の組み合わせが、キー不要・JSON・系列名つきという点で
既存の e-Stat ダッシュボード (ADR-0007) と同等の品質を持つため、一括ダウンロードとの
比較で明確に上回る。

新規アダプタ `src/lib/adapters/boj.ts` を作り、短観 (#228) と SPPI (#338) の両方で
共有する。日付変換は DB ごとに専用関数を持つ (`toQuarterlyDate`/`toMonthlyDate`、
他アダプタの同名関数とは別実装)。

## 実装時の注意点

- **`pnpm verify` に照合を追加する**。FRED 同様キー不要でネットワークアクセスできるため、
  項目 1 (一次情報との照合) にそのまま組み込める
- **クレジット表示を `/terms` に追加する** (利用規約ページの出所一覧に日銀を追加)
- **短観とBSI (#226) は同じ図に載せない**。公表元 (日銀 vs 財務省・内閣府) も対象
  (規模×業種 vs 規模のみ) も違うため、#116〜#118 と同じ「重ねずに切り替える」原則を適用する
- **四半期の描画は #226 で確立済み** (月次グリッド + `connectNulls`) をそのまま使う。
  追加の作り込みは不要
