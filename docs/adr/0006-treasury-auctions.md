# ADR-0006: 国債入札は米財務省 Fiscal Data API から取る

- 状態: 採用
- 日付: 2026-08-18
- 関連: #96 / #87 (財政収支) / ADR-0004 (指標マスタ)

## 背景

参考記事が国債入札の結果を市場の転換材料として扱っている。

> 10年債の入札は低調で財政収支も市場予想より悪化したこともあり再び金利が上昇し株価の上値は抑えられ

`docs/spec.md` の将来構想にも「債券入札」がある。応札倍率 (bid-to-cover = 応札額 ÷ 落札額) が
低いほど買い手が弱く、金利上昇圧力になる。既に取得している財政収支 (発行額の背景) の
**下流**にあたる指標で、経路として繋がる。

FRED には入札結果が無い。

## 候補

| 案 | 無料枠 | キー | 履歴 | 運用負荷 |
| --- | --- | --- | --- | --- |
| **A. 米財務省 Fiscal Data API** | 制限の記載なし | **不要** | 359 件 (1979〜) | 低。JSON をそのまま読む |
| B. TreasuryDirect の旧 API | 同上 | 不要 | 同等 | 中。Fiscal Data に統合されつつあり将来性が低い |
| C. HTML スクレイピング (財務省の発表ページ) | — | 不要 | 個別ページを辿る必要 | 高。構造変更で壊れる |

## 判断

**A を採用**。

- **API キーが不要**。公開リポジトリで秘密情報を持たない方針 (spec の制約) と噛み合う
- 週次に 1 回しか叩かないので、レート制限があっても問題にならない
- JSON なので stockanalysis (HTML スクレイピング) のような構造変更の脆さが無い
- B は Fiscal Data への統合が進んでおり、新規採用する理由が無い
- C は A があるので不要

## 不適合点

- **A**: 入札は不定期 (10 年債は月 1 回だが日付が動く)。週次グリッドに載らないため、
  月次ビューに「その月の入札結果」として載せる実装が要る
- **A**: 全期間を毎回取り直す。件数が小さいので差分取得はしない (複雑さに見合わない)

## 系列の特定 (実データで確認)

**3 つの条件をすべて満たさないと別物が混ざる**。

| 条件 | 外すとどうなるか |
| --- | --- |
| `security_type = Note` | 債券 (Bond)・割引債 (Bill) が混ざる |
| `original_security_term = 10-Year` | **リオープン (追加発行) が漏れる**。残存期間で「9-Year 10-Month」と記録されるため |
| `inflation_index_security = No` | **10 年 TIPS が混ざる**。2026-07-23 の入札で利回り 2.438% として実際に確認 |

3 条件を満たす件数は 359 件。直近は次のとおりで、利回りが通常債の水準 (4% 台) に揃う。

| 入札日 | 年限の記録 | 応札倍率 | 最高利回り |
| --- | --- | --- | --- |
| 2026-08-12 | 10-Year | 2.53 | 4.683% |
| 2026-07-08 | 9-Year 10-Month | 2.59 | 4.580% |
| 2026-06-10 | 9-Year 11-Month | 2.57 | 4.538% |

`security_term` だけで絞った場合は 223 件になり、リオープンが落ちて TIPS が混ざる。
**#66 の `RSCCASN` (衣料品店の小売売上を全体と取り違えかけた) と同じ失敗パターン**なので、
アダプタ側でも受信データの `inflation_index_security` を検証して落とす。

## 履歴の境界 (実データで確認)

359 件のうち **81 件 (1979-10-31 〜 1999-08-11) は応札倍率が記録されていない**。
提供の境界であって破損ではないので、アダプタでは欠測として飛ばす。
実際に使えるのは **1999-11-10 以降の 278 件**。

## 閾値

**「低調」の線は引かない**。応札倍率にどこから低調かの定説が無く、恣意的な基準になる
(VIX・イールドスプレッド・貯蓄率と同じ判断)。過去の水準と比べて読む。
