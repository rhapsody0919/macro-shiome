# ADR-0011: 発表予定カレンダーは FRED の Release API と FactSet の休刊予告から組み立てる

- ステータス: 採用
- 日付: 2026-08-24
- 関連: #270

## 背景

FactSet の Earnings Insight レポートが 2026-08-14・08-21 の 2 週連続で休刊だった件をきっかけに、
「次はいつ更新されるか」が画面から分からず、バッチが壊れていると誤解される余地があると判明した
(#270)。ヘッダーの鮮度バッジ (#11) は**過去の実績**しか示さず、**未来の予定**を示す経路が無かった。

## 検討した選択肢

macro-shiome の 8 つのデータソースのうち、指標の大半 (約 90 件) を占める FRED と、
今回の発端になった FactSet を中心に、次回発表日の入手性を実データで検証した。

| データソース | 一次情報での検証結果 | 判断 |
| --- | --- | --- |
| **FRED** | `fred/release/dates` API (`include_release_dates_with_no_data=true`) が未来の発表予定日を返すことを確認済み。ウェブの Release Calendar ページ (`/releases/calendar?rid=X`) でも CPI (rid=10) が 2026年9月〜12月分、Employment Situation (rid=50) が同様に確認できた。既存の `FRED_API_KEY` で使え新規の秘密情報は不要 | **採用** |
| **FactSet** | 実際の PDF (2026-08-07号) 本文に "Author's Note: The report will not be published on [日付]... The next edition will be published on [日付]." という一貫した書式の予告を確認。ただし**この予告は休刊が起きる週にしか載らない**。通常週は「次の金曜日」という固定周期で計算できるため、自由文の抽出が要るのは例外ケースだけ | **採用** (周期計算 + 休刊予告の抽出) |
| 米財務省 Fiscal Data (国債入札) | 既存の `auctions_query` エンドポイントで `auction_date` が未来の行を検索したが 0 件。**このエンドポイントは完了済みの結果データのみ**で、将来の予定入札は持たない | 見送り (現状のAPIでは取れない) |
| 統計ダッシュボード / e-Stat | 各省庁が公表予定カレンダーを別途持つ可能性はあるが未検証 | 見送り (#270 の調査で保留) |
| Finnhub / Tiingo (ETF) | 市場休場日以外は毎営業日更新なので「予定日」という概念が薄い | 対象外 (カレンダー化の意味が無い) |

## 決定

**FRED の Release API と FactSet の休刊予告 (無ければ周期計算) から発表予定カレンダーを組み立てる。**
財務省・統計ダッシュボードは今回のスコープに含めない。予定日が不明な指標は「不明」と明示し、
古い日付を出し続けない (#270 の受入基準どおり)。

## 理由

- FRED は指標の大半を占めており、この 1 経路でカバレッジが最大になる
- FactSet は今回の発端そのものであり、対応しないと元の問題が解決しない
- どちらも実データで検証済みで、推測に頼っていない
- 財務省・統計ダッシュボードは「未検証」であって「取れないと確認した」わけではない。
  #135/#170 で「取れないと書く前に調べ直す」教訓があるとおり、必要になった時点で
  別 Issue として調査する

## 実装方針

- FRED は指標マスタに 1 件足すだけで自動的にカレンダーにも乗るよう、**手作業でどの指標を
  対象にするかを選ばない** (ADR-0004 の設計を踏襲)。`fred/series/release` で系列が属する
  リリースを調べ、同じリリースに属する指標をまとめて 1 行にする (CPI 関連系列が個別の
  行に分かれると冗長なため)
- FactSet は `resolveFactsetNextIssueDate` が休刊週の連続に対応する。当該週の号が 404 でも、
  直近で取得できた号まで遡って休刊予告を探す (最大 8 週)。予告が見つからず遡りきったら
  「不明」に倒す

## 影響・トレードオフ

- FRED の指標数ぶん (約 90 系列) `fred/series/release` の呼び出しが日次バッチに増える。
  FRED は 120 req/min の余裕があり、既存の観測値取得と合わせても無料枠に収まる
- ローカル環境に `FRED_API_KEY` が無かったため、`data/views/release-calendar.json` の
  初期値は一部の指標 (CPI・Employment Situation・FactSet) についてブラウザで個別に確認した
  実データで構築したプレースホルダーになっている。マージ後に `daily.yml` を手動実行し、
  実際のバッチ (GitHub Actions Secrets の `FRED_API_KEY` を使用) で全指標ぶんに更新されることを
  確認する
- 財務省・統計ダッシュボードの発表予定は対象外のまま。将来必要になれば別 Issue で調査する
