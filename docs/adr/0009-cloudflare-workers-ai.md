# ADR-0009: AI要約のLLMはCloudflare Workers AIを使う

- ステータス: 採用
- 日付: 2026-08-23
- 関連: #279 (AI要約機能)

## 背景

投資家×エンジニアの議論で、指標データをAIに要約させ「経済はどのような状態か」「注意が必要なことはあるか」「狙い目なセクター/ETFはあるか」を提示する機能の実装が決まった。無料スタックの制約 (完全無料、公開リポジトリ) の中でLLMをどこから呼ぶかを検討した。

**当初の第一候補だった GitHub Models は不採用にした。** 2026-07-30付けで完全廃止されており、実機で `gh models run` を試したところ `410 Gone` (`github_models_retirement_brownout`) が返る。公式ドキュメント (docs.github.com/en/github-models) も廃止通知のみで、レート制限ページ自体が404。検証以前にサービスが存在しない。

## 検討した選択肢

| 評価軸 | Cloudflare Workers AI | Google Gemini API |
| --- | --- | --- |
| 無料枠 | **10,000 neurons/日** (00:00 UTC リセット)。公式ページで数値確認済み | 無料枠ありクレジットカード不要。**モデル別のRPD/RPM/TPMは公式ドキュメントに数値が無く**、要ログインのAI Studio画面依存 |
| 1日1回・数千〜1万トークンの要約用途での余裕度 | 入力8,000+出力800トークン想定で、小型Llama (1B) 約34 neurons・8B(fp8-fast) 約61 neurons・Mistral-7B 約94 neurons。**いずれも無料枠の1%未満** | 公式に数値が無いため試算不可。第三者ブログの数値はサイト間で食い違い、一次情報で裏取りできなかった |
| 認証・秘密情報 | APIトークンを **`Workers AI - Read`/`Write` のみに絞れる** (アカウント全体ではない) | APIキー1本。IP/オリジン/スコープ制限は可能 |
| 新規登録の要否 | **不要** (既にCloudflare Pages/Workersでホスティング済みのアカウントを流用) | 新規にGoogleアカウント/AI Studioでキー発行が必要 |
| データ利用ポリシー | 公式に「学習・サービス改善への利用は明示的同意なしには行わない」と明記 | **無料枠は「製品の改善に使用され人間レビューもあり得る」と明記** (有料化で解消) |

各案の不適合点:

- **Cloudflare Workers AI**: 小型Llamaモデルは要約品質がGemini Flash系に劣る可能性がある (一次情報だけでは判断できず、実装後に実データで確認する必要がある)。Llamaは Meta のライセンス条項が別途適用される (Third-Party Services)
- **Google Gemini API**: 無料枠のレート制限が公式に非公開で、実装前に個人のGoogleアカウントでAI Studioにログインして確認する追加の手間が要る。無料枠のデータが製品改善・人間レビューに使われる点は、指標データの要約とはいえ公開リポジトリで運用するサービスとして相性が悪い

## 決定

**Cloudflare Workers AIを採用する。** モデルは `@cf/meta/llama-3.1-8b-instruct-fp8-fast` を使う (1B系より要約品質が見込め、無料枠消費は8Bでも無料枠の1%未満で問題にならないため)。

## 理由

- 無料枠の余裕が一次情報の数値で具体的に確認できた (Geminiは確認できなかった)
- 既存のCloudflareアカウントを流用でき、新規の秘密情報管理コストが増えない (公開リポジトリで秘密情報を増やすほど露出面が広がるという既存方針、ADR-0007と同じ判断)
- データ利用ポリシーが公開リポジトリでの運用に対して明確に安全側
- APIトークンをWorkers AI専用スコープに絞れ、漏洩時の被害範囲を限定できる

## 影響・トレードオフ

- **数値・シグナルはコードが計算し、LLMには言語化のみさせる。** 投資家×エンジニアの議論で合意した設計方針で、LLMのhallucinationで数値が捏造されるリスクを構造的に無くす (詳細は #279 の実装で扱う)
- APIトークン (`CLOUDFLARE_AI_API_TOKEN` 想定) はGitHub Actions Secretsのみで管理し、ログ・コミット・クライアントバンドルに出さない (FRED / Finnhub / Tiingo と同じ扱い)
- 小型モデルの要約品質は実装後に実データで確認する。品質が不十分なら `@cf/meta/llama-3.1-8b-instruct` (非fp8、ニューロン消費6倍) への切り替えを検討する余地を残す (それでも無料枠の余裕は大きい)
- Geminiのレート制限非公開は今回の調査の限界。将来Geminiを再検討する際は自分のGoogleアカウントでAI Studioに実際にログインして確認する必要がある
