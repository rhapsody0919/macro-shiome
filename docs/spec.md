# spec — macro-shiome

作成: 2026-08-16 / SDD Step 1

**案件タイプ: UI 案件**

## 0. プロジェクトのゴール

**株式投資の判断に使う指標を 1 つの Web アプリに集約する。** 証券口座のチャートでは横断的に見づらい
指標 (バリュエーション・マクロ・セクター) をまとめて表示し、相場の潮目を読めるようにする。

段階を分ける。**v1 = バリュエーション** (本 spec の対象)、**v2 = 市場サマリー** (7 節)。
v1 を先にするのは、EPS / PER の取得経路の調査が完了しており手戻りが無いため。

なお、参考にしている分析者の記事そのものを転載するのではなく、**同じ指標を自分でデータソースから
集めて表示する**方針とする (他者の著作物を再配布しない)。

## 1. 機能要件

優先度 P1 = v1 必須 / P2 = v1 に入れる (落としても致命的でない) / P3 = v2 以降。

### F-1 週次バッチ (P1)

GitHub Actions が **UTC 土曜 02:00 (JST 土曜 11:00)** に実行し、下記データ仕様の全指標を取得して
**JSON としてリポジトリに commit** する (ADR-0001)。JST 土曜早朝ではなく午前遅めにするのは、
FactSet が金曜発行で当日号がまだ公開されていない恐れがあるため (plan 4-1)。

受入基準:
- cron は UTC 指定で JST 土曜朝に相当すること (JST = UTC+9)
- 同じ週に再実行しても行が重複しない (一意キー = 指標種別 + 観測日)
- いずれかの指標の取得に失敗したら job が失敗 (赤) になる。成功分のみコミットして緑にしない
- 手動実行 (`workflow_dispatch`) ができる
- FactSet PDF が 404 の週 (休刊週) は「欠測」として記録し、job は成功扱いとする (F-10)

### F-2 Chart 1: 指数 vs EPS (二軸折れ線) (P1)

左軸に指数、右軸に Forward 12M EPS と Trailing 12M EPS。

受入基準:
- 3 系列が 1 つのチャートに描画され、左右軸のスケールが独立している
- EPS 2 系列は**導出値**である旨をチャート内に明示する (D-11 / D-12)
- **Trailing EPS は決算シーズン中は毎週動く**。S&P 500 は 500 社の決算が数週間にわたり順次発表され、TTM の構成四半期が毎週入れ替わるため。決算閑散期はほぼ横ばいになる
- NASDAQ も同じ形式で表示する。ただし NASDAQ は Forward EPS を持たない (3 節 D-17)
- **指数を非表示にして EPS 系列だけを見るモード**を用意する (二軸だと EPS の細かい動きが潰れるため)
- **過去最高値の自動マーカー** (P1): 各 EPS 系列について、その時点までの最高値を更新した週にマーカーを打つ。参考にしている分析では毎週手作業で「(過去最高値)」と注記されている要素であり、自動化の価値が高い。ツールチップに更新幅を出す
- **前週比**を数値で併記する (絶対値と %)

### F-2 補足: 数値の水準について (2026-08-16 決定)

一般に流通している S&P 500 の EPS は **bottom-up (operating) ベースの blended 値**で、本アプリが自動取得できる FactSet 基準 (as-reported、trailing は CY 単位) とは **約 9% ずれる**。

| | 一般的な値 (bottom-up) | 本アプリ (FactSet 基準) |
| --- | --- | --- |
| S&P 500 実績 EPS | 298.14 (PER 25.99) | 273.4 (PER 28.2) |
| S&P 500 予想 EPS | 363.48 (CY 固定) | 385.5 (forward 12M ロール) |
| NASDAQ 100 実績 PER | 33.98 | 33.62 (QQQ、近い) |

**水準を一致させることは v1 の目的としない** (取得の確実性を優先)。上下の動き・前週比・過去最高値の更新タイミングは同じように追えるため、目的は達成できる。ただし他の情報源と数値を突き合わせたときに食い違うため、**定義と基準を画面に明記する** (F-11)。

### F-3 Chart 2: Forward P/E と基準線 (P1)

S&P 500 の Forward 12M P/E の推移に、5 年平均・10 年平均の基準線を重ねる。

受入基準:
- 基準線は FactSet PDF から毎週取得した最新値を使う (固定値をハードコードしない)
- 基準線の値と取得時点を画面に表示する
- 現在値が基準線の上か下かが一目で分かる

### F-4 Chart 3: イールドスプレッド (P1)

株式益回り − **実質金利** の推移。

**2026-08-16 に定義を修正**した。当初は「株式益回り − 名目 10 年債利回り」としていたが、
実務では**実質金利**と比較する。インフレ調整後で株と債券を比べるためで、値も大きく違う
(実測: 実質金利ベース 2.29% に対し名目ベースだと 0.02%)。

受入基準:
- 株式益回り = 1 ÷ Forward 12M P/E × 100 (%)
- **実質金利 = 名目 10 年債利回り (`DGS10`) − 期待インフレ率 (`T10YIE`)**。定義を画面に明記する
- 検証: 記事の実測値と FRED が一致することを確認済み (期待インフレ率 2.27% = `T10YIE` 2.27、
  実質金利 2.41% ≒ `DFII10` 2.39)。`DFII10` (10 年 TIPS 利回り) は実質金利の直接系列なので、
  参照値として併記してもよい
- S&P 500 と NASDAQ-100 の両方について算出する
- 両者とも % 表記に統一する (小数表記との混在は不可)
- ゼロ線を引き、スプレッドの符号が判別できる

**水準の読み方 (2026-08-17 追加、#52)**。数値だけでは高いか低いか判断できないため、
読み方と現在の水準を示す。

- **固定の「危険水準」は置かない**。「◯% を切ったら危険」という線には定説が無く、
  恣意的な基準になる (VIX に補助線を引かなかったのと同じ判断。plan U-S1)
- 客観的に言えるのは次の 2 つだけ。この 2 つだけを示す
  1. **ゼロ** (株式益回り = 実質金利) の境目
  2. **過去の分布における現在の位置** — 実データから求めるので恣意性が入らない
- 過去 5 年の平均と ±1σ を補助線として表示する
- 現在値のパーセンタイルを文言で示す (例: 「過去 5 年で下位 16% の水準」)
- 分布の窓は**期間フィルターに追従しない**。フィルターで基準が動くと比較にならないため
- 標本が 10 未満なら分布を出さない (相関と同じ基準。少数の標本では偶然で大きく振れる)
- 実測 (2026-08-07、S&P 500): 平均 3.70% / σ 1.23 / n 168、現在 2.60% は下位 16%

### F-13 理論値と割高率 (P1)

**「割安か・適正か・割高か」に直接答える要件**。プロジェクトのゴールの中核。

受入基準:
- **理論値 = 実績 EPS ÷ 基準益回り**
- **割高率 = 1 − (理論値 ÷ 実際の指数値)**。正なら割高、負なら割安
- **基準益回りは設定値**として持ち、画面から変更できる。外部から取得できる値ではなく、
  成長率見通しに基づく裁量パラメータであるため
- 初期値: **S&P 500 = 3.67%、NASDAQ-100 = 3.27%** (下記の理由)
- 基準益回りの変更履歴 (いつ・いくつに・なぜ変えたか) を残せるようにする。
  成長率の前提が変われば見直す性質の値のため
- 理論値・割高率が**基準益回りの設定に依存する**旨を画面に明記する。客観的な絶対値ではない

**初期値の根拠**: 一般に流通する bottom-up EPS 基準では S&P 500 = 4.0% / NASDAQ-100 = 3.2% が
使われる (実績 EPS 298.14 ÷ 4% = 理論値 7453.5、指数 7748.5 に対し 3.81% の割高)。
本アプリの EPS は as-reported 基準で約 9% 低いため、同じ基準益回りを使うと割高率が過大に出る
(11.8%)。**基準益回り側で系統差を吸収する**ことにし、同じ理論値になる 3.67% を初期値とする
(273.4 ÷ 7453.5 = 3.67%)。NASDAQ-100 は QQQ の PER が元々近いため 3.2% → 3.27% と微調整で済む。

### F-5 相関サマリー Card (P1)

S&P 500 指数と Forward 12M EPS の相関係数を、直近半年・直近 1 年・全期間で表示する。

受入基準:
- ピアソン相関係数。週次データ点で計算する
- 両系列に値がある週のみ使う (片方欠測の週はペアで除外。0 埋めしない)
- 各期間の標本数 n を併記する
- n < 10 の期間は数値を出さず「データ不足」と表示する

### F-6 期間切り替えフィルター (P1)

1 年 / 3 年 / 5 年 / 全期間。

受入基準:
- 全チャートと相関サマリーが同一の期間範囲を参照する (一部だけ別の窓を見ない)
- 系列ごとに蓄積開始時点が異なる (指数 10 年 / Forward P/E 5 年 / NASDAQ の PER は蓄積開始以降) ため、選択期間にデータが無い系列は空状態を出す
- 「全期間」= 蓄積済みの全範囲

### F-7 追加指標チャート (P2)

VIX・USDJPY・10 年債利回りの推移。

受入基準:
- 3 指標それぞれの単体チャートを表示する
- 期間フィルターが効く

### F-8 個人消費 (PCE) チャート (P3)

受入基準:
- 月次データであることを明示し、週次系列と同一チャートに混在させない

### F-12 予想改定チャート (P1)

アナリスト予想が先週・先月と比べて上がっているか下がっているかを見る。**本アプリの主目的の 1 つ**。

受入基準:
- CY2026 / CY2027 の予想成長率の週次推移を折れ線で表示する (対象年は毎年繰り上がる)
- 進行中四半期の blended 成長率について、**「今週 / 先週 / 四半期末」の 3 時点**を並べて表示する。
  この 3 点は FactSet PDF 本文に毎週明記されているため、蓄積が無くても初週から表示できる
- 前週差 (ポイント) を符号つきで併記する。上昇 = 予想の上方修正
- 売上成長率も同じ形式で表示する (任意、P2)
- **forward 12M EPS の推移と混同させない**。forward 12M は四半期が進むと対象期間がロールするため、
  改定が無くても増益トレンド下では上昇する (週あたり約 0.3% のバイアス)。改定を純粋に見るのは
  CY 固定の成長率の方であることを画面に注記する

### F-9 初回バックフィル (P1、初回のみ)

受入基準:
- 指数・DGS10・VIX・USDJPY: FRED から 10 年分 (FRED の S&P 500 提供上限)
- S&P 500 の Forward / Trailing P/E **と成長率 3 時点**: 過去の FactSet 週次 PDF を 5 年分遡って取得。
  **5 年遡及が可能なことは実測で確認済み** (2021〜2025 年の金曜サンプル 15 件がすべて 200、
  2020-08-07 も 200)。404 になるのは夏季休刊週のみ (2026 年は 8/14・8/21、2023 年は 8/11 以降、
  2022 年 8 月)。約 250 ファイル、1 件あたり間隔を空けても 20 分程度で完了する見込み
- バックフィルにより、**予想改定の推移 (F-12) を蓄積を待たず初日から 5 年分表示できる**
- NASDAQ の PER: **バックフィル不可** (stockanalysis.com は現在値のみ)。蓄積開始以降のみ
- 過去 PDF の取得はレートに配慮し、間隔を空けて実行する
- 取得できなかった週は欠測として記録し、後から再取得できる

### F-10 欠測の可視化 (P2)

受入基準:
- FactSet 休刊週・取得失敗週はチャート上で線を繋がない (前方補完しない)
- 最終更新日時と、直近の欠測有無をダッシュボードに表示する

### F-11 出所表示・規約対応 (P1)

受入基準:
- FRED 規約の必須文言をページに目立つ形で表示する: `This product uses the FRED® API but is not endorsed or certified by the Federal Reserve Bank of St. Louis.`
- 本アプリの利用規約ページを設け、FRED API Terms of Use へのリンクと「本アプリの利用により FRED API 規約に同意したことになる」旨を記載する (FRED 規約が他ユーザー向けアプリに課す義務)
- 各指標に出所 (S&P Dow Jones Indices / Nasdaq / FactSet / stockanalysis.com / FRB / CBOE) と著作権表示を併記する。stockanalysis.com は規約が「出所明記」を条件にスニペット利用を認めているため、出所表示は必須
- **EPS / PER が as-reported (GAAP) ベースである旨を明記する** (3 節「定義の選択」参照)
- ホスト名に `fred` を含めない。FRED / FactSet のロゴを使わない

## 2. スコープ

### やること (v1)

- S&P 500 / NASDAQ 指数、Forward・Trailing の P/E と EPS (導出)、イールドスプレッド
- VIX・USDJPY・10 年債利回り
- 週次バッチ、初回バックフィル、ダッシュボード、期間フィルター、相関サマリー

### やらないこと (v1)

- **個別銘柄の表示・分析** (指数レベルのみ)
- **アラート・通知** (メール / Slack / Push)
- **ユーザー認証・複数ユーザー** (全面公開・単一ビュー)
- **売買推奨・投資助言に当たる表示** (指標の提示に留める)
- **operating (継続事業) ベースの EPS / PER** (3 節「定義の選択」参照)
- **EPS 絶対値の一次取得** (無料経路が存在しないため導出で代替)
- **NASDAQ の Forward P/E** (取得経路が存在しない)
- **NASDAQ 総合 (`NASDAQCOM`)** (PER 経路が無いため NASDAQ-100 を採用。6 節 U-10 参照)
- **日次更新** (週次のみ)
- **債券入札・景気指標の網羅** (PCE のみ P3 で検討、他は v2 以降)
- **モバイルアプリ** (Web のみ)
- **市場サマリー (日経平均・ゴールド・ドル指数・セクター別騰落率)** → v2 で扱う (7 節)。
  取得経路は調査済みなので、v1 完成後に着手できる

## 3. データ仕様

### 定義の選択: as-reported (GAAP) ベースに統一

S&P 500 の EPS には 2 系統ある。**本アプリは as-reported (GAAP) に統一する** (2026-08-16 決定)。

| 系統 | 内容 | 実測値 (2026-08 時点) | 自動取得 |
| --- | --- | --- | --- |
| as-reported (GAAP) | 会計基準どおりの実績。一時要因を含む | S&P 500 PER 28.2 (FactSet) / 28.00 (SPY) | **可** |
| operating (継続事業) | 一時要因を除いた本業ベース。約 9% 高く出る = PER は低く出る | S&P 500 PER 25.99 (EPS 298.14) | **不可** |

operating を採用しない理由: 週次の一次ソースは S&P Global 公式 `sp-500-eps-est.xlsx` だが、
curl は 403 (Akamai)、ブラウザでも "Access Denied" で、ヘッダを実ブラウザに寄せても取得できなかった
(2026-08-16 実測)。無人バッチで安定取得する手段がない。

**この選択の帰結**: 一般的な投資レポート (operating ベースが多い) と本アプリの PER は約 9% ずれる。
同じ指数でも数字が食い違って見えるため、画面に「as-reported (GAAP) ベース」と明記する (F-11)。

### OCR を採用しない理由 (2026-08-16 実測)

PDF の p.31-32 には Bottom-Up EPS の実績・推定が**データラベル付きのグラフ画像**として載っており、
目視では読める (CY2025 = 274.74、CY2026 = 358.66、CY2027 = 405.17、四半期別も Q424〜Q327)。
しかし tesseract 5.5.1 による OCR は実用に耐えなかった。

| 解像度 | 結果 |
| --- | --- |
| 300dpi | 12 個中 4 個のみ正読。軸ラベルと混在し対応付け不能 |
| 600dpi | 改善せず。**誤読が発生** (89.20 → 69.20、65.78 → 65.76) |

欠落は検知できるが、もっともらしい誤読は検知できない。金融データで silent な誤りが蓄積するのは
許容できないため不採用とする。代わりに D-18 / D-19 の成長率から EPS を復元する (下記 D-21)。

**D-15 / D-16 は ETF の PER であり、指数そのものの PER とは厳密には一致しない**
(構成銘柄の加重方法・保有現金・時点の差)。実測でも SPY 28.00 に対し FactSet の指数ベース 28.2。
S&P 500 は FactSet (指数ベース) を正とし、SPY は検証用に留める。NASDAQ 100 は QQQ 以外に
無料経路が無いため D-15 を採用し、ETF ベースである旨を画面に明記する。

### 導出値

| --- | --- | --- | --- |

| CY2026 推定 = 273.4 × 1.300 | 355.4 | 358.66 | 0.9% |

**EPS の絶対値をテキスト層として取得できる無料経路は存在しない** (2026-08-16 時点、実測で確認)。
値自体は FactSet PDF のグラフ画像に載っているが、OCR は誤読のため不採用 (上記)。

- FactSet PDF の「Bottom-Up EPS Estimates」ページ (p.31-32) はテキスト量 0 (画像内のラベルとしては存在)
- insight.factset.com の週次記事 HTML にも EPS 絶対値の記載なし (成長率 % のみ)
- S&P Global 公式 `sp-500-eps-est.xlsx` は 403、ブラウザでも Access Denied
- Yardeni の無料週次 PDF は 2023-12-28 で更新停止、かつ数値は図表画像
- WSJ「P/Es & Yields on Major Indexes」(出所 Birinyi Associates、毎週金曜更新) は数値が JS レンダリングで、内部 API の直接呼び出しは 400。ブラウザ側もポリシーで開けず検証不能
- Yahoo Finance chart API は 429、Stooq CSV は JS proof-of-work チャレンジで機械取得不可

したがって EPS はすべて「指数 ÷ PER」の導出値とし、画面上で実データと区別する。
S&P 500 の除算に FRED の指数ではなく PDF 内の終値 (D-9) を使うのは、P/E と時点を完全に一致させるため。

### 検証用の独立ソース (任意)

導出値の妥当性検証にのみ使う。定期取得はしない。

- multpl.com の月次実績 EPS (取得実測 OK、robots.txt に Disallow なし)
- Shiller `ie_data.xls` (Yale、1871 年〜、旧 .xls 形式)

### 要件からの変更点

当初要件の基準線「5 年平均 19.5 倍 / 10 年平均 18.0 倍」は現在の実値と異なる
(2026-08-07 時点の FactSet 実値は 5 年平均 19.9 / 10 年平均 19.0)。
かつ毎週更新されるため、**固定値を使わず PDF から取得した最新値を使う** (F-3)。

## 5. 制約・前提

- **完全無料スタック**。課金しない。無料枠 (GitHub Actions の実行時間、FRED のレート制限、Cloudflare Pages のビルド回数) を設計制約として扱う
- **リポジトリは public**。API キーをコード / コミット / ログ / クライアントバンドルに残さない。秘密情報は GitHub Actions Secrets のみ。**配信は静的 JSON なのでクライアントに秘密情報が一切出ない** (ADR-0001)
- **ダッシュボードは全面公開**。ただし S&P 500 (S&P DJI)・NASDAQ (Nasdaq OMX)・FactSet はいずれも著作権付きで、FRED 規約は「個人利用を超える場合は権利者の許可が必要」と明記している。**この点は承知の上で公開する判断をした** (2026-08-16)。緩和策として F-11 を実装必須とする。権利者から要請があれば当該系列の公開を停止する
- **FactSet PDF には休刊週がある** (2026-08-14 / 08-21 が実例)。URL に日付が入るため休刊週は 404 になる。これを異常ではなく欠測として扱う
- **PER / EPS は as-reported (GAAP) ベース**。一般的な投資レポートの operating ベースとは約 9% ずれる (3 節)
- **NASDAQ 100 の PER は ETF (QQQ) 由来**で、指数そのものの PER とは厳密には一致しない
- 技術スタック (フロント / ホスティング / チャートライブラリ) は未確定。SDD Step 2 で選定する

### v2 で明記が必要な注意点

- **「DXY」は FRED に無い**。一般に DXY と呼ぶ ICE U.S. Dollar Index (EUR 57.6% など 6 通貨構成) と、
  FRED の `DTWEXBGS` (貿易加重) は**別の指数**で水準も違う (DTWEXBGS 119 に対し DXY は 100 前後)。
  **「ドル指数 (貿易加重)」と正しい名前で表示する** (2026-08-16 決定)。DXY と同一視しない
- **FRED に金の現物価格は無い** (あるのは PPI・輸出入物価指数のみ)。GLD (ETF) で代替するため、
  金現物価格ではなく信託の経費率分だけ乖離することを明記する
- セクター別騰落率も指数ではなく ETF ベース

### 指標の追加方針

参考にしている分析者の記事から指標を特定し、**その指標のデータを自分でデータソースから集めて**
表示する。記事の文章・図表・分析内容そのものは転載しない (著作権)。
追加のたびに (1) 取得経路の実測 (2) 利用規約と著作権の確認 (3) 定義の一次情報での裏取り
を行い、`docs/adr/` に記録する。

**U-10 (NASDAQ の指数対象) は解消**: 当初要件の「NASDAQ」を **NASDAQ-100 に確定** した (2026-08-16)。
理由は、PER を取得できる QQQ が NASDAQ-100 連動であり、NASDAQ 総合 (`NASDAQCOM`) を採用すると
指数と PER の対象がずれてバリュエーション分析が成立しないため。FRED `NASDAQ100` は長期履歴があり、
2026-08-14 = 30,046.14 を実測確認済み。
